Challenges & Enterprise SaaS Vulnerabilities
Problem Statement
Cognitive Fatigue & Meeting Overload
Back-to-back synchronous video conferences degrade human attention. Critical action items, technical requirements, and verbal commitments are lost to rapid context switching.
Third-Party Data Sovereignty & NDA Barrier
Commercial cloud bots (Otter.ai, Fireflies) stream raw audio to external server farms, exposing confidential corporate discussions to severe NDA and GDPR compliance risks.
Recurring Subscription Overhead
Commercial cloud assistants charge $15–$35 per user every month. For academic departments and growing engineering teams, recurring licensing costs scale unsustainably.
Network Uplink Jitter & Intrusive Bots
Cloud transcription fails during connection drops. Furthermore, commercial bots inject disruptive notices into meeting lobbies, discouraging open and candid deliberation.

Three-Tier Microservice Topology
System Architecture
1. Tier 1: Presentation Client (React 18 + Vite) Tailwind CSS dashboard for meeting scheduling, real-time status indicators, timestamped transcript search, and grounded RAG chat modal.
2. Tier 2: Central Orchestrator (Node.js + Express) Manages JWT authentication, meeting metadata in local MongoDB, and runs a node-cron 60-second polling daemon for automated bot dispatch.
3. Tier 3: Edge AI Worker (FastAPI Microservice) Orchestrates Playwright Chromium automation, kernel audio recording, faster-whisper STT, ChromaDB vector indexing, and local Llama 3.2 inference.
4. Local Air-Gapped Storage Volumes Persistent local disk directories for WAV audio recordings (/data/recordings), formatted text (/data/transcripts), and DuckDB vector storage.

Ensuring Sub-3.0 GB RAM Ceiling on Workstations
Memory Management & Edge Optimization
• Sequential Model Lifecycle Audio recording, Whisper STT, text embedding, and Llama 3.2 inference run in discrete sequence. Memory spikes are prevented by loading only one model at a time.
• Dynamic Weight Release The STT acoustic model is immediately deallocated from RAM after transcribing the WAV file, freeing ~1.15 GB before the language model initializes.
• 4-Bit Weight Quantization (Q4_K_M) Reduces Llama-3.2-3B memory footprint from 12.0 GB (FP32) to under 2.0 GB, maintaining 99% of original conversational accuracy on standard CPU.
• Hardware-Friendly Workstation Deployment No dedicated Nvidia CUDA GPU required. The entire pipeline executes smoothly on Intel Core i5/i7 and AMD Ryzen CPUs with 8GB or 16GB total RAM.
